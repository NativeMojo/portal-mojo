# portal-mojo (the package)

The React portal toolkit for django-mojo. Ships as **TypeScript source** via
subpath exports — consumers compile it with their own Vite + TS
(`moduleResolution: "bundler"`); there is no build step here. Marked
`private` until the Phase 2 publish plan lands (see repo `PLAN.md`).

## Subpath surfaces

| Subpath | Surface |
|---|---|
| `portal-mojo/client` | Typed django-mojo protocol layer: envelope unwrap at exactly one boundary (a failed save **rejects**), `start`/`size` paging, `'-field'` sort, Django lookups, the URL-synced `useTableParams` store (single source of truth for table state), TanStack Query hooks. The in-memory mock transport lives here too — it is the wire contract's executable spec and evolves in lockstep with the client. |
| `portal-mojo/ui` | Mission-control UI: `ModelTable`, `FilterBar`/`FilterPills`, `SchemaForm`/`formModal`, `DetailView`, awaitable native-`<dialog>` `modal`, `toast`, `ThemeProvider`, `Badge`/`MetricCard`/`Spark`, `fmt` formatter namespace. |
| `portal-mojo/charts` | Dependency-free SVG charts: `SeriesChart` (line/bar/area, stacked bars, legend toggle, crosshair tooltip) and `MetricsChart` (granularity/range/type control bar for `/api/metrics/fetch`). |
| `portal-mojo/admin` | Admin **section bundles**, dual-mount: the standalone back-office portal mounts all of them at root; a product portal embeds them under a "System" area. Contract (`AdminSection`) only today; sections land as Phase 2 pages stabilize. |

## What the consuming app must provide

- **Theme tokens + component CSS.** Components render semantic classes
  (`panel`, `chip`, `tbl`, …) styled by the app's `theme.css` under
  `data-theme="light"` **and** `"dark"` (reference set:
  `apps/portal/src/theme.css`).
- **Tailwind scan of this package.** In the app CSS:
  `@source "../../../packages/portal-mojo/src";` — utility classes used in
  package components are generated by the app's Tailwind pass.
- **bootstrap-icons.** Components emit `bi bi-*` classes; the app imports the
  icon font once.
- **Providers.** `QueryClientProvider`, a hash router (`useTableParams` is
  built on react-router's `useSearchParams`), `ThemeProvider`, plus `ModalHost`
  and `ToastHost` mounted once in the shell.
- **`VITE_MOJO_API`.** Unset → the in-package mock transport (dev default);
  set to a django-mojo origin → the real backend, same code path.

## Rules

The non-negotiables live in the repo root `PLAN.md` ("Architecture rules") and
`CLAUDE.md`. Short list: params store owns table state; one envelope-unwrap
boundary; failure is unmissable; controlled inputs only; models are
definitions + hooks (TanStack Query owns cache); `ReactNode` slots, never
trusted-HTML strings; both themes from day one.
